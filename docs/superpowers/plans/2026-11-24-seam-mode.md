# Emenda Mode + Live Strip in Racha-tema — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Emenda game mode (`seam`): 2–10 players, regrouped each round into pairs or trios, each drawing a hidden zone plus live shared strips, revealed per round and at the end. Give Racha-tema the same live middle strip.

**Architecture:**
- **Shared geometry:** one pure module, duplicated on server and web like the protocol types, defines zones and strips for a group of 2 or 3.
- **Live strips:** each browser draws its own transparent layer. It sends PNG snapshots of its part of each strip (`strip-frame`), and the server relays each snapshot only to the neighbour across that strip and keeps the latest.
- **Final pictures:** a picture is white paper plus, per member, the kept strip frames and then the submitted full layer.

**Tech Stack:** TypeScript, `ws` server (node:test via tsx), Next.js 15 / React 19 / Tailwind v4 web, Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-11-24-seam-mode-design.md`. Read it first: the geometry, protocol limits and compose rule are defined there.

## Global Constraints

- UI name **Emenda**. Mode id `seam` in code, protocol, files and DB. UI copy pt-BR; code, comments and commits in English.
- Canvas 800×600 logical. Strip width **100**.
  - Pair: A `0–350`, strip `350–450`, B `450–800`.
  - Trio: A `0–200`, S0 `200–300`, B `300–500`, S1 `500–600`, C `600–800`.
- Seam rooms:
  - 2–10 players, capacity 10;
  - rounds clamp 1–5;
  - turn 15–300 s;
  - no theme, no voting, no score.
- Seam phases are `seam-drawing`, `seam-reveal` (10 s × `timeScale`) and `seam-final`. `seam-final` is in `FINAL_PHASES` (play-again).
- `strip-frame` limits:
  - PNG data URL only;
  - ≤ 150 KB (string length of the data URL);
  - ≤ 15 frames/s per player per strip (excess dropped silently);
  - current round only;
  - relayed only to the neighbour across that strip, never broadcast.
- Client sends a strip frame at most once per 100 ms per strip when it changed, plus on pointer-up.
- Own layer is transparent. Eraser and fill act only on the own layer. The neighbour's frames are a separate layer.
- Racha-tema always has the strip (not an option); sit-out stays; no trios. Monstrinho and Caricatura a dois are unchanged.
- Clean switch: party layers become full 800×600 transparent PNGs, with no support for the old 400-wide halves.
- Gallery key for seam: `"round:groupId"`, with `DrawingRef.pairId` carrying the group id.
- Mode toy image: `mode-party` (reuse) until Emenda has its own art.
- Mode copy (pt-BR): "Emenda", "De 2 a 10 jogadores", "Cada um desenha escondido na sua faixa. Na emenda com o vizinho, vocês se veem ao vivo. No fim, o desenho aparece inteiro."

## Review Focus

1. **A trio's middle player sends a frame for strip 1:** only player C gets it, never A. (Task 3 test "trio: each strip reaches only its neighbour".)
2. **A player reloads mid-round:** they get back the neighbours' latest frames and their own kept frames, and their strip work is in the final picture. (Task 3 test "rejoin replays frames"; Task 2 test "kept frames ride along in results".)
3. **A frame arrives after the round changed, from the sit-out, or from someone in another pair:** it is dropped, with no error and no relay. (Task 3 tests.)
4. **The group's size changes mid-round** (a trio member leaves): the round goes on, and that zone is blank but their strip frames stay. With fewer than 2 players the game ends in `seam-final`. (Task 2 tests.)
5. **Flood fill in the strip next to the neighbour's strokes:** it fills only the own layer and never paints over the neighbour's lines. (Task 6 unit test on the layer hook's fill, using an own-layer-only boundary.)
